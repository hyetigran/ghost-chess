# Guests use Supabase Anonymous Auth instead of a custom guest_id scheme

Guests are full online players who need to be invited and matched (PRD §4.3), which means their identity has to be shared. The existing scheme (`src/lib/auth/guest-auth.ts`, `supabase/schema.ts`) generates a client-side UUID stored in local storage, trusted bare by `set_guest_id`/RLS with no expiry, rotation, or proof of possession — a scheme built for "no account needed," not for "identity that gets handed to other people," which is what an invite flow requires. Sharing it for matchmaking would leak a permanent bearer credential for every game that guest has ever played.

We decided to migrate guests onto Supabase's built-in Anonymous Sign-in: guests get a real `auth.users` row and a signed JWT, so `auth.uid()` works identically for guests and registered users. This removes `white_guest_id`/`black_guest_id`, `guest_conversions`, `set_guest_id`, and the custom local-storage identity entirely — "guest vs. registered" becomes a boolean on the user row, and invites reference a game ID, never an identity credential. We rejected keeping the custom scheme and merely constraining how it's shared, since that leaves a weaker, parallel auth system in place indefinitely rather than removing it.
