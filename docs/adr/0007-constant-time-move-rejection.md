# Illegal-move handling must not leak occupancy via response timing

Move rejection (see [CONTEXT.md](../../CONTEXT.md)) is designed to give zero signal about *why* a move was illegal, closing the one leak vector left after [ADR-0001](./0001-server-side-redaction.md)'s server-side redaction. Response *content* being uniform isn't enough on its own — if checking "is the destination secretly occupied by an opponent piece" costs measurably more than a purely geometric illegality check, an attacker could recover occupancy from response latency alone, even though every response looks identical.

We decided this doesn't require new engineering (chess.js-style legality checking already touches the same board data regardless of why a move fails), but it does require discipline: illegal-move handling must not branch into reason-specific code paths that do different amounts of work — no early-return "fast path" for geometrically-obvious illegal moves that skips full board evaluation, and no extra work (logging, audit writes) on only one illegal-move branch. Legal vs. illegal timing differences are fine (the player already learns that from the move succeeding); only illegal-for-which-reason needs to stay indistinguishable. We rejected building dedicated timing-safety machinery (artificial delay/jitter) as unnecessary complexity — real mobile network latency variance already dominates any realistic computational difference here, and a per-user rate limit on move attempts (wanted for other reasons anyway) further blunts the residual risk.

The same principle rules out how "move confirmation" (PRD §2.4) can be built: it must be purely client-side UX (an "are you sure?" prompt based on what the player already sees), with the move sent to the server exactly once, at commit, through the same single validation path as an unconfirmed move. A two-step server exchange — "is this move legal?" then "confirm" — would create a second, free-standing legality oracle a player could probe repeatedly without ever committing a real move, undermining this same guarantee.
